# Webnovel Import · 网文资料导入

**0.3.0 候选构建 · 2026-11-07。** 在 Obsidian 里搜索起点、番茄、七猫和晋江作品，导入作品资料。下架、无链接或没有平台 ID 的作品，也可以先手动建档。支持独立 Markdown 和 Media Core 两种保存方式。

项目仓库见 [threeyang3/webnovel-import](https://github.com/threeyang3/webnovel-import)。源码、可安装文件和各验证阶段的证据随仓库维护。详见 [验证记录](docs/validation.md) 与 [数据接口约定](docs/data-contract.md)。

## 搜索并导入第一部作品

1. 在 Obsidian 命令面板运行 **搜索网文作品**，输入书名或作者，在要搜索的平台旁点击 **在 Obsidian 搜索**。晋江官网表单会带入关键词，选择 **作品** 或 **作者** 后，点击官网的搜索按钮。
2. 在官网结果里点开书名。作品详情加载后，插件会打开导入预览。整个流程无需安装书签或复制作品链接。
3. 核对书名、作者和来源，点击 **导入作品**，或交给 **Media Core** 确认保存。取消预览会回到搜索窗口，可点 **后退** 继续选书，或点 **更换搜索** 改关键词。

如果官网显示验证页，可以按页面提示操作。书名和作者正常显示后，点 **预览当前作品** 再试一次。内嵌搜索需要桌面版 Obsidian 1.8.3 或更新版本。如果当前版本或网页无法正常使用内嵌搜索，点 **在外部浏览器打开官网搜索**。晋江会打开官网表单。

## 手动添加与后补来源

运行 **手动添加网文作品**，也可以在搜索弹窗点 **手动添加作品**，带入当前关键词。书名必填。作者、简介、Vault 内图片路径或 HTTP(S) 封面、首发年份或日期、原作状态、显示字数与分类均可选填。失效的历史平台链接与资料备注保留在本地参考区。

原作状态选 **未知（留空）** 后，日后可从正式来源补入连载、完结或暂停。手工填写的确定状态与人工清空继续受保护。

兼容的 Media Core 会打开确认预览，支持打开已有同名 Work 或确认新建。未安装、停用或缺少手动建档接口时，可以明确确认独立保存。独立笔记拥有本地 UID 和空来源列表。

以后找到可信来源时，在该笔记运行 **给当前作品关联正式网文来源**，或在导入预览中选择已有候选。核对目标路径后保存。独立手动笔记也可在配套 Media Core 预览中确认原位交接首条正式来源。原 UID、人工填写或清空的字段和正文继续受保护。

## 把网文资料交给 Media Core

1. 在同一 Vault 启用两个插件。四平台托管与手动预览需要配套的 Media Core 0.12.3 开发构建。保留默认的 **自动** 模式，或在 Webnovel Import 设置中选择 **Media Core**。
2. 从搜索结果点开作品，进入导入预览。已经有作品链接时，也可运行 **从链接导入网文作品**，再点击 **获取资料**。
3. 点 **导入 Media Core**，核对已有归属或选择候选，检查字段差异和保护说明后确认。保存完成可点 **打开作品**。后续重新采集同一链接，走相同入口更新原作品。

从当前笔记指定目标时，该笔记需有有效 UID，并且属于 Core 识别的已关联作品、候选或交接目标。

**只安装 Webnovel Import。** 自动模式确认未安装 Media Core 后显示 **导入作品**。也可在设置中明确选 **独立**，继续用 schema 1 和本地封面。独立模式会拒绝修改 Media Core 托管作品。

**交接现有独立笔记。** 打开该文件，运行 **将当前网文交给 Media Core**，选一个已保存的来源，再点 **导入 Media Core**。核对 **确认原位交接** 所显示的路径后提交。交接保留原文件、UID、个人记录、旧来源及采用记录。若交接中断，重新采集同一来源并交给 Media Core 可继续。归属冲突或格式异常时请先核对原文件。详见 [规范交换与托管约定](docs/data-contract.md#media-core-规范交换)。

**Media Core 0.12.2 或暂时不可用。** 点 **复制规范来源 JSON**。在已启用的 Media Core 中运行 **导入来源资料**，粘贴并生成预览，核对后确认。自动模式遇到已安装但停用、尚未加载或接口不兼容的 Core 时会提示原因。指定当前作品时，手动备用流程中也要核对目标路径。

## 独立模式的重复作品候选

单条预览会优先定位相同 `provider + id` 的笔记；已明确关联的多来源继续定位同一 Work。没有相同来源时，按笔记属性的完整书名与作者集合提示候选，包括手工创建、尚无来源的笔记。无作者的手动建档也可按同名提示候选，关联须逐条确认。仅统一 Unicode 全半角、大小写和连续空白，不做模糊书名匹配，不凭文件名猜作者。

出现候选后，必须选择一个已有笔记或“独立创建作品”再保存。关联只追加来源并沿用字段保护，不覆盖个人文字；独立创建保留候选笔记。修改书名、作者或重新获取资料会重置候选选择。保存时重新检查来源归属，防止同一来源被关联到另一笔记；已删除的目标会拒绝写入。

批量导入遇到候选时，该条不写入，显示原因及“单独处理”入口，其余条目继续执行；待选择条目目前计入未成功项。没有引入跨插件关联表或模糊自动合并。候选测试结果见验证记录。

## 插件定位

- 提供书名、作者、封面、简介和可取得的连载资料。
- 平台作品 ID 只作为来源标识；新作品另有独立本地 `uid`。
- 个人阅读状态、进度、评分、简评、随记、标签、系列关系由本地维护。
- 只处理你在搜索窗口主动选中或提交详情页链接的作品。
- 一本网文按一个作品处理。纸书版本、改编作品与系列组织由使用者的知识库规则决定。

本插件可独立运行，也可与 Media Core 或其他来源插件共存。独立导入的属性是本插件的约定，接入已有知识库时可先核对字段与模板。

## 安装

1. 打开项目仓库，切换到要安装的构建分支，选择 **Code → Download ZIP**，然后解压。也可以直接下载该分支中的 `main.js`、`manifest.json`、`styles.css`。见 [Webnovel Import](https://github.com/threeyang3/webnovel-import)。
2. 把上述三个文件放入当前 Vault 的 `.obsidian/plugins/webnovel-import/`。请不要把整个源码目录作为插件文件夹嵌套放入。
3. 重启 Obsidian，在第三方插件中启用 **Webnovel Import**。
4. 到插件设置选择导入模式。独立模式下，新作品目录和封面目录默认分别为 `网文/` 和 `_assets/webnovel-import/`。

仓库同步维护源码和构建文件 `main.js`，手动安装不需要先配置开发环境。更新时可下载同样的三个文件替换旧文件，再重新加载插件；保留安装目录中的 `data.json` 可保留插件设置。作品笔记和封面保存在 Vault 中。

本版尚未发布 GitHub Release，也未上架 Obsidian 插件市场。插件声明的桌面版最低版本为 1.5.0。旧版客户端可使用 **从链接导入网文作品** 等入口。

## 浏览器辅助导入

如果作品已在外部浏览器打开，可以用书签作为备用采集入口。番茄也可直接使用 **从链接导入网文作品**。

1. 在 Webnovel Import 设置中点击 **复制采集书签**。
2. 在常用浏览器新建一个书签，命名为“采集当前网文作品”；编辑它的**网址栏**，粘贴刚复制的完整内容，保留开头的 `javascript:`。这是书签代码，不需要粘贴进开发者控制台。书签绑定复制时所在的 Vault；换库时重新复制。
3. 正常打开起点、七猫或晋江作品详情页，等书名、作者和简介显示后，点击该书签。
4. 书签将解析后的资料复制到**本机剪贴板**，并请求打开 Obsidian。若浏览器询问是否打开 Obsidian，可选择允许。核对预览后点 **导入 Media Core** 或 **导入作品**，按钮取决于导入模式。
5. 如果没有自动切回 Obsidian，手动运行 **“从浏览器采集结果导入”**。如果浏览器不允许直接复制，采集书签会显示可手动复制的资料；复制完整内容后再运行该命令。

书签复用插件的解析器，通过剪贴板传送书名、作者、简介、封面地址及连载资料。点击书签会替换剪贴板中的原内容。自动回传会核对 Vault、平台、作品 ID 和采集时间。写入笔记和下载封面均发生在确认预览之后。

已有作品想补关联时，先在该笔记执行 **给当前作品关联正式网文来源**，填写作品链接并点击 **“打开作品页”**，再点浏览器采集书签。匹配的采集结果会回到所选笔记的关联预览。已有同一来源的作品重复采集时，继续使用原去重与人工字段保护规则。

备用方法：正常打开作品页并另存为 HTML，在导入弹窗填写对应链接后点击 **“选择 HTML 文件”**。文件中的作品 ID 必须与链接相符。刷新失败会打开带有当前笔记和来源链接的补充导入弹窗；批量失败项可点击“单独处理”。

在隔离 Vault 中，用户点击 Safari 书签采集《诡秘之主》，冷启动 Obsidian 1.15.0 后自动显示作品预览。点 **导入 Media Core** 后，Core 定位到已有作品并显示 **更新已关联作品**。这是 0.2.0 构建的预览验收。安装版本与采集记录见 [验证记录](docs/validation.md)。

## 使用入口

在 Obsidian 命令面板搜索 `Webnovel Import`：

| 命令 | 用法 |
|---|---|
| 搜索网文作品 | 在 Obsidian 打开官网搜索，点开作品结果进入导入预览 |
| 手动添加网文作品 | 填写书名和可选资料，预览并创建无外部来源的本地作品 |
| 从链接导入网文作品 | 粘贴链接 → 获取 → 按需补填 → 导入；失败时可手工补填或提供 HTML |
| 从浏览器采集结果导入 | 读取采集书签写入的剪贴板资料 → 预览 → 确认导入；不自动写笔记 |
| 批量导入网文作品链接 | 每行一个链接，按来源 ID 去重。独立模式逐条导入，Core 路径先获取，再逐条预览确认。某条失败时其余条目继续 |
| 给当前作品关联正式网文来源 | 打开已有作品 Markdown 后执行；把来源接到该文件，不再新建一个同名作品 |
| 刷新当前网文的来源资料 | 独立模式下逐个刷新当前作品的来源。托管作品可重新采集同一链接并交给 Media Core |
| 将当前网文交给 Media Core | 从独立笔记选择已保存的来源，打开 Core 原位交接预览，或复制规范来源 JSON |

支持的作品链接形态：

```text
https://fanqienovel.com/page/7143038691944959011
https://www.qidian.com/book/1010868264/
https://book.qidian.com/info/1010868264/
https://m.qidian.com/book/1010868264/
https://www.qimao.com/shuku/195958/
https://www.jjwxc.net/onebook.php?novelid=4001734
https://m.jjwxc.net/book2/4001734
```

本版不解析章节链接、关键词落地页、短链接或搜索页。起点和晋江的不同详情页地址统一保存规范作品 URL，并按同一作品 ID 去重。正常浏览器页面采集和普通 HTTP 获取分别记录。

**表单留空表示本次不采纳该字段。** 若要清除已有值，请直接编辑作品属性；后续刷新会保护对原采用值的人工清空。导入表单不会绕过已有人工字段的保护去强制替换。

## 字段及“年份”的含义

| 信息 | 本地采用字段 | 来源区内容 |
|---|---|---|
| 本地身份 | `uid` | 不依赖外部 ID |
| 书名 | `title` | 平台原始书名 |
| 作者 | `authors` | 作者名称列表 |
| 封面 | `cover` | `cover_url` 原始图片地址；下载成功时采用本地图片路径 |
| 简介 | `summary` | `description` 来源简介；本地简介默认最多 260 个 Unicode 码点，长度可调 |
| 网文首发年份 | `first_published_year` | 仅明确来源或人工补填；当前公开样本未取得可靠首发字段，自动留空 |
| 作品连载状态 | `serialization_status` | `ongoing` / `completed` / `paused`；不同于你的阅读状态 |
| 分类/标签 | 不写入个人 `tags` | 来源 `tags` |
| 字数 | 不强制换算成精确数字 | `word_count_text` 保留如“320.1万字”的网站精度 |
| 更新与章节 | 不作为首发时间 | `last_updated_at`、`latest_chapter` |

`last_updated_at` 保存页面原始显示值，不凭空添加时区。`fetched_at` 为插件获取时间。首发年、实体书出版年、付费上架年、最新更新年、抓取年均不混用；不会从简介中的获奖年份推断首发年。

番茄的长数字作品 ID 全程保存为字符串，以免 JavaScript 数字精度损失。

## 独立模式更新时怎样保护你的内容

1. 新建作品时填入来源资料，并生成独立 `uid`。
2. 给已有作品补来源时，只填没有内容且没有人工清空记录的字段。
3. 同一来源刷新时，只有本地值仍等于上次自动采用值，才自动更新。
4. 你改过或清空过的值保留。表单中补填/修改的非空值会标为人工采用。
5. 来自另一来源的已有采用值不被新来源抢占。跨平台同名作品不会仅因书名相同自动合并；使用“关联当前作品”明确指定。
6. 本轮缺失的字段不清空已知值。来源区若沿用旧字段，`retained_fields` 标记该字段最后获得的时间。
7. 临时封面下载失败时，已有可用本地封面保留；新条目仍可保留远端图片地址。

**正文只在首次创建时生成。** 初始标题、简介和封面是当时的可读快照，之后刷新只改属性中的来源区及允许更新的采用字段，不重绘正文。当前采用值以属性为准；正文可以自由整理。该边界避免覆盖个人文字，但意味着正文里的旧简介不会自动跟随来源更新。

插件不改文件名，不搬动已有作品，不创建单独的随记文件，也不自动更改 Series。关闭插件后，Markdown、属性和已下载封面仍留在 Vault。

## 数据格式与源码

插件的追踪信息放在 `webnovel_import` 下：

- `schema_version: 1`：仅表示该插件命名空间版本。
- `sources`：以 `provider + id` 匹配的来源记录。
- `adopted`：各采用字段的上次值、来源归属，以及人工补填证据。手动建档时记录本地字段的基线，后续清空仍受保护。
- `manual_reference`：可选历史平台、链接和资料备注。与正式来源记录分开保存。

这些信息用于来源追踪和更新保护，不建议手改。未知版本会明确拒绝覆盖目标文件。其他文件的格式问题不会阻断所有导入，但会报告未参与去重检查的路径。

详细边界见 [docs/design.md](docs/design.md)，验证证据见 [docs/validation.md](docs/validation.md)。

开发构建：

```bash
npm ci
npm run build
npm test
```

使用 Node.js 22 或兼容的新版本。运行时使用 Obsidian API 与浏览器 DOM；构建及测试工具仅作为开发依赖。

修改源码后，应运行构建并将更新后的 `main.js` 与源码一并提交，确保仓库直接安装文件与源码保持一致。

```text
src/types.ts       来源模型、设置与标识
src/sources.ts     适配器注册表、链接路由与公共解析校验
src/adapters/      来源接口、四平台适配器、共享 DOM 工具
src/merge.ts       字段采用、人工保护、多来源记录
src/importer.ts    网络请求、封面、去重与 Vault 写入
src/media-core-integration.ts  Core 发现、API 版本与预览调用
src/ui.ts          单条与批量导入界面
src/search*.ts     官网搜索地址与弹窗
src/manual-*.ts    无来源作品草稿与建档界面
src/main.ts        插件生命周期、命令与设置
```
