# Webnovel Import · 网文资料导入

**0.1.1 开发预览，2026-11-01。** 一个独立编写的 Obsidian 插件，从网文作品详情页取得作品资料并保存为本地 Markdown。首批来源为番茄小说与起点中文网。

项目仓库：[threeyang3/webnovel-import](https://github.com/threeyang3/webnovel-import)。

本版已包含可安装的 `main.js`、`manifest.json`、`styles.css`，以及完整源码。**番茄直接获取已有真实样本验证；起点已取得两部正常浏览器作品页，并完成资料解析和真实封面验证，新增浏览器采集书签与 HTML 文件导入。** 起点的普通 HTTP 请求仍可能返回验证页面；浏览器书签到真实 Obsidian 的完整操作链路尚待实测。这是可供安装联调的开发基线，不是稳定发布或插件市场上架声明。

## 当前开发状态（未发布）

来源适配器架构已完成：起点、番茄各自管理链接识别、身份校验、字段解析和失败提示，注册表统一路由；核心导入、字段合并和 Vault 写入不包含平台分支。新增平台需先核验真实页面，再实现适配器并注册，详见 [架构说明](docs/design.md#六来源适配器架构未发布)。当前安装文件保持 0.1.1 版本号，是包含本次重构的本地开发构建，未发布新版本。

Sandbox 实测已通过起点 HTML 重复导入（UID 与正文保持不变）、番茄真实 HTTP 获取及导入、两站本地封面显示。**浏览器实际点击书签 → 剪贴板权限 → 协议唤起的完整链路：待验收。** 本机剪贴板与 URI 接收端此前已单独验证，不等于完整书签验收。下面的平台历史基线以 [最新验证记录](docs/validation.md) 为准。

## 插件定位

- 提供书名、作者、封面、简介和可取得的连载资料。
- 平台作品 ID 只作为来源标识；新作品另有独立本地 `uid`。
- 个人阅读状态、进度、评分、简评、随记、标签、系列关系由本地维护。
- 只处理你主动提交的作品链接，不自动导入推荐书、同作者其他书、分卷或章节。
- 一本网文按一个作品处理。纸书版本、改编作品与系列组织由使用者的知识库规则决定。

本插件独立运行，可与其他信息源插件共存。它只管理自己的来源记录与允许采用的作品字段，不修改其他插件的配置。当前属性是本插件的试用约定，接入已有知识库时应先检查字段与模板是否匹配。

## 平台支持的真实状态

| 来源 | 已实现 | 已验证 | 当前限制 |
|---|---|---|---|
| 番茄小说 | 标准作品链接识别、作品元数据解析、结构化封面提取 | 《十日终焉》原始 HTML 解析成功；真实封面 HTTP 200 且人工目视确认 | 只有一个作品的真实页面样本完成代码级验证；Obsidian 内网络与界面尚待实测 |

起点的“获取资料”和批量获取仍使用普通 HTTP；遇到验证页面会明确报错。可改用下文的浏览器采集方式，或在同一弹窗选择正常作品页另存的 HTML。插件不会把验证页保存为空作品，也不会自动解验证码、导入 Cookie 或执行获取页面中的脚本。

## 安装

1. 打开[项目仓库](https://github.com/threeyang3/webnovel-import)，选择 **Code → Download ZIP**，然后解压。也可以直接下载仓库中的 `main.js`、`manifest.json`、`styles.css`。
2. 把上述三个文件放入当前 Vault 的 `.obsidian/plugins/webnovel-import/`。请不要把整个源码目录作为插件文件夹嵌套放入。
3. 重启 Obsidian，在第三方插件中启用 **Webnovel Import**。
4. 到插件设置检查新作品目录与封面目录。默认分别为 `网文/` 和 `_assets/webnovel-import/`。

仓库同步维护源码和构建文件 `main.js`，手动安装不需要先配置开发环境。更新时可下载同样的三个文件替换旧文件，再重新加载插件；保留安装目录中的 `data.json` 可保留插件设置。作品笔记和封面保存在 Vault 中。

本版尚未发布 GitHub Release，也未上架 Obsidian 插件市场。声明最低 Obsidian 版本为 1.5.0，并暂时设为桌面插件；没有声称在该历史版本或移动端实测。

## 起点：浏览器辅助导入

这条路径让浏览器正常显示作品页，再把其中的作品资料带回插件，不必逐项手填。

1. 安装或更新至本版，在插件设置中点击 **“复制采集书签”**。
2. 在常用浏览器新建一个书签，命名为“采集起点作品”；编辑它的**网址栏**，粘贴刚复制的完整内容，保留开头的 `javascript:`。这是书签代码，不需要粘贴进开发者控制台。书签绑定复制时所在的 Vault；换库时重新复制。
3. 正常打开起点作品详情页，等书名、作者和简介显示后，点击该书签。
4. 书签将解析后的资料复制到**本机剪贴板**，并请求打开 Obsidian。若浏览器询问是否打开 Obsidian，可选择允许。资料进入预览表单，核对后点击 **“导入作品”**。
5. 如果没有自动切回 Obsidian，手动运行 **“从浏览器采集结果导入”**。如果浏览器不允许直接复制，采集书签会显示可手动复制的资料；复制完整内容后再运行该命令。

书签复用插件的解析器，只传书名、作者、简介、封面地址及连载资料；不传整页 HTML、Cookie 或账户凭据，也没有第三方采集服务。点击书签会替换剪贴板中的原内容。自动回传还会核对作品 ID，避免误用另一部作品的旧剪贴板资料；写入笔记和下载封面均发生在确认预览之后。

已有作品想补关联时，先在该笔记执行“给当前作品关联起点或番茄来源”，填写起点链接并点击 **“打开作品页”**，再点浏览器采集书签。匹配的采集结果会回到所选笔记的关联预览。已有同一来源的作品重复采集时，继续使用原去重与人工字段保护规则。

备用方法：正常打开作品页并另存为 HTML，在导入弹窗填写对应链接后点击 **“选择 HTML 文件”**。文件中的作品 ID 必须与链接相符。刷新失败会打开带有当前笔记和来源链接的补充导入弹窗；批量失败项可点击“单独处理”。

目前验证的是两部作品的浏览器页面、解析及采集脚本的数据传递逻辑；尚未把书签、浏览器权限、系统协议处理与真实 Obsidian 界面串联实测。普通 HTTP 获取限制仍单独保留，不将辅助导入写成无人值守批量抓取已经恢复。

## 五个使用入口

在 Obsidian 命令面板搜索 `Webnovel Import`：

| 命令 | 用法 |
|---|---|
| 从作品链接导入网文 | 粘贴链接 → 获取 → 按需补填 → 导入；失败时可手工补填或提供 HTML |
| 从浏览器采集结果导入 | 读取采集书签写入的剪贴板资料 → 预览 → 确认导入；不自动写笔记 |
| 批量导入网文作品链接 | 每行一个链接；按来源 ID 去重，逐条处理，某条失败不阻断后续，可停止后续导入 |
| 给当前作品关联起点或番茄来源 | 打开已有作品 Markdown 后执行；把来源接到该文件，不再新建一个同名作品 |
| 刷新当前网文的来源资料 | 逐个刷新该文件已记录的来源；按字段保护规则采用新值 |

支持的作品链接形态：

```text
https://fanqienovel.com/page/7143038691944959011
https://www.qidian.com/book/1010868264/
https://book.qidian.com/info/1010868264/
https://m.qidian.com/book/1010868264/
```

本版不解析章节链接、关键词落地页、短链接或搜索页。起点来源统一保存规范作品 URL；移动或旧地址也按同一作品 ID 去重。正常浏览器页面采集和普通 HTTP 获取分别记录。

**表单留空表示本次不采纳该字段。** 若要清除已有值，请直接编辑作品属性；后续刷新会保护对原采用值的人工清空。导入表单不会绕过已有人工字段的保护去强制替换。

## 字段及“年份”的含义

| 信息 | 本地采用字段 | 来源区内容 |
|---|---|---|
| 本地身份 | `uid` | 不依赖外部 ID |
| 书名 | `title` | 平台原始书名 |
| 作者 | `authors` | 作者名称列表 |
| 封面 | `cover` | `cover_url` 原始图片地址；下载成功时采用本地图片路径 |
| 简介 | `summary` | `description` 来源简介；本地简介默认最多 260 个 Unicode 码点，长度可调 |
| 网文首发年份 | `first_published_year` | 仅明确来源或人工补填；当前两站适配器未取得可靠首发字段，自动留空 |
| 作品连载状态 | `serialization_status` | `ongoing` / `completed` / `paused`；不同于你的阅读状态 |
| 分类/标签 | 不写入个人 `tags` | 来源 `tags` |
| 字数 | 不强制换算成精确数字 | `word_count_text` 保留如“320.1万字”的网站精度 |
| 更新与章节 | 不作为首发时间 | `last_updated_at`、`latest_chapter` |

`last_updated_at` 保存页面原始显示值，不凭空添加时区。`fetched_at` 为插件获取时间。首发年、实体书出版年、付费上架年、最新更新年、抓取年均不混用；不会从简介中的获奖年份推断首发年。

番茄的长数字作品 ID 全程保存为字符串，以免 JavaScript 数字精度损失。

## 更新时怎样保护你的内容

1. 新建作品时填入来源资料，并生成独立 `uid`。
2. 给已有作品补来源时，只填没有内容且没有人工清空记录的字段。
3. 同一来源刷新时，只有本地值仍等于上次自动采用值，才自动更新。
4. 你改过或清空过的值保留。表单中补填/修改的非空值会标为人工采用。
5. 来自另一来源的已有采用值不被新来源抢占。跨平台同名作品不会仅因书名相同自动合并；使用“关联当前作品”明确指定。
6. 本轮缺失的字段不清空已知值。来源区若沿用旧字段，`retained_fields` 标记该字段最后获得的时间。
7. 临时封面下载失败时，已有可用本地封面保留；新条目仍可保留远端图片地址。

**正文只在首次创建时生成。** 初始标题、简介和封面是当时的可读快照，之后刷新只改属性中的来源区及允许更新的采用字段，不重绘正文。当前采用值以属性为准；正文可以自由整理。该边界避免覆盖个人文字，但意味着正文里的旧简介不会自动跟随来源更新。

插件不改文件名，不搬动已有作品，不创建单独的随记文件，也不自动更改 Series。关闭插件后，Markdown、属性和已下载封面仍留在 Vault。

## 数据格式与源码

插件的追踪信息放在 `webnovel_import` 下：

- `schema_version: 1`：仅表示该插件命名空间版本。
- `sources`：以 `provider + id` 匹配的来源记录。
- `adopted`：各采用字段的上次值、来源归属，以及人工补填证据。

这些信息用于来源追踪和更新保护，不建议手改。未知版本会明确拒绝覆盖目标文件。其他文件的格式问题不会阻断所有导入，但会报告未参与去重检查的路径。

详细边界见 [docs/design.md](docs/design.md)，验证证据见 [docs/validation.md](docs/validation.md)。

开发构建：

```bash
npm ci
npm run build
npm test
```

使用 Node.js 22 或兼容的新版本。运行时使用 Obsidian API 与浏览器 DOM；构建及测试工具仅作为开发依赖。

修改源码后，应运行构建并将更新后的 `main.js` 与源码一并提交，确保仓库直接安装文件与源码保持一致。

```text
src/types.ts       来源模型、设置与标识
src/sources.ts     适配器注册表、链接路由与公共解析校验
src/adapters/      来源接口、起点与番茄适配器、共享 DOM 工具
src/merge.ts       字段采用、人工保护、多来源记录
src/importer.ts    网络请求、封面、去重与 Vault 写入
src/ui.ts          单条/批量导入界面
src/main.ts        插件生命周期、命令与设置
```

## 网络与后续开发

执行获取时访问你指定的起点或番茄作品页；下载封面时访问该页提供的图片地址，或你手工填写的图片地址。本版没有登录凭据、后台扫描、遥测、小说正文下载或平台写回。没有账号书架同步、站内搜索及全库定时刷新。

优先后续工作是：在真实 Obsidian 中验证番茄直接获取和起点浏览器采集的完整操作链路，再依据实际使用的模板改进字段映射。新平台、搜索与书架功能逐项评估。本仓库当前提供 0.1.1 开发预览；尚未发布 Release、上架插件市场或完成真实 Obsidian 验收。
