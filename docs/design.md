# 网文信息源插件 · 开发边界

日期：2026-11-01。实现版本：0.1.1 开发预览。

## 一、产品目标

Webnovel Import 是一个独立 Obsidian 信息源插件，从起点中文网、番茄小说等网络文学平台获取作品的封面、简介、作者、年份等资料。平台负责提供作品资料；个人简评等内容保存在本地知识库中。

设计原则是：以 Obsidian 本地文件为核心；本地作品身份独立于平台；采用信息、来源记录与个人数据分层；一个作品可关联多个来源；只收录主动选择的作品；保留人工内容。

## 二、本版采取的实现选择

以下是 0.1.1 的实现选择。这些约定限定于本插件，不要求整个 Vault 采用相同的数据模型。

| 事项 | 本版选择 | 对未来的约束 |
|---|---|---|
| 名称 | Webnovel Import / webnovel-import | 仓库为 threeyang3/webnovel-import，当前提供开发预览 |
| 插件范围 | 一个插件内有多个来源适配器 | 无须每个平台各装一份相同导入逻辑 |
| 主入口 | 具体作品 URL | 不以平台个人书架或账号作为前提 |
| 作品粒度 | 一整部网文为一个条目 | 不按章节、分卷自动拆 Work；外传/续作另行判断 |
| 本地身份 | 新条目生成 work-UUID | 平台 ID 不取代本地身份 |
| 来源去重 | provider + 字符串 id | 同名不等于同作品 |
| 跨源汇入 | 用户在已有作品上执行关联来源 | 不把标题模糊匹配结果直接当同一实体 |
| 默认目录 | 网文/，可改 | 既有作品继续保留原路径 |
| 本地简介 | 默认截短为 260 个 Unicode 码点 | 可调整；不生成新的 AI 简介，不扩写内容 |
| 年份 | 明确网文首发年份 | 没有证据就留空，支持人工补填 |
| 正文 | 首次创建静态可读快照，后续保留 | 最新采用值在属性中；后续模板/渲染器可单独开发 |
| 随记与系列 | 不在本版自动生成 | 由用户或其他知识库工具维护 |

本版的手工补填仍要求一个已识别的来源链接。没有平台来源的作品可以由用户直接创建 Markdown，或通过其他知识库工具管理；本插件暂不提供无来源建档入口。

## 三、三个逻辑数据层

**来源层**保存网站值及出处，例如作者、原始简介、分类、显示字数、最近更新和真实封面 URL。每条记录有平台、作品 ID、规范 URL、获取时间和获取方式。`acquisition` 可以是 remote、browser、html 或 manual，分别记录普通 HTTP、正常浏览器页面采集、用户提供 HTML 与手工输入。

**本地采用层**保存当前作品使用的 title、authors、summary、cover、first_published_year、serialization_status。首次补空、后续三方比较的规则决定是否采用新值。用户的修订有优先权；同一个 Work 可以逐渐增加其他来源。

**个人层**包括用户阅读状态、阅读进度、评分、简评、笔记、个人标签和系列关系。插件不写这些字段。平台完结状态属于作品状态；用户读完属于个人状态，两者分别表达。

逻辑分层不要求复杂的嵌套 YAML。此版只有插件自己管理的信息放进 `webnovel_import`，通用采用字段放在顶层，方便其他工具读取。接入已有 Vault 时，应对照实际模板检查字段映射。

## 四、获取策略与可行性

番茄页面的可见 HTML 提供作品资料，但封面 DOM 的 src 在核验样本中是灰色加载占位图。适配器优先使用同一作品 JSON-LD 内的图片地址，只接受匹配当前作品的结构化对象；DOM 封面只作为备用，并排除已核验的占位图。不执行网页脚本，也不把作者签名或其他作品推荐当简介。

起点普通 HTTP 请求仍返回 202 验证页面，但正常浏览器可以展示本轮核验的两部作品。0.1.1 在真实页面基础上增加作品 DOM 解析与采集书签：用户正常打开作品后点击书签，由同一解析器提取资料，通过本机剪贴板和 Obsidian URI 返回预览，确认后才写入。采集脚本不导出 Cookie 或整页 HTML，不调用第三方服务；正常网页自身由浏览器加载，插件不执行获取页面中的验证脚本。来源标为 browser，与普通 HTTP 成功明确区分。

备用 HTML 导入支持文件选择，核对页级 URL／作品 ID；推荐列表中的其他作品不作为页面身份。刷新失败可打开已选定目标笔记的补充导入弹窗，仍沿用原有人工内容保护。首发年没有可靠的作品级证据时留空，不采用目录章节日期。

没有找到并核验适用于此任务的正式公开元数据 API 文档，不能把未找到解释为 API 一定不存在。本版使用公开作品详情页，不依赖没有核验的第三方下载接口。

## 五、克制的开发顺序

1. 在真实 Obsidian Vault 的小范围样本中验证番茄：获取、预览、封面、写入、重复导入、人工修订后刷新。
2. 在真实客户端完成起点浏览器书签、剪贴板权限、URI 唤起、预览写入及已有笔记关联的联调；普通 HTTP 限制单独记录。
3. 根据实际使用的其他信息源插件与 Vault 模板改进字段映射，不批量迁移或改名旧笔记。
4. 再决定站内搜索、账号书架、更多平台、可配置模板、Series 自动组织的接口。

本仓库同步维护源码及可直接安装的 `main.js`，目前不附带持续集成工作流。当前状态应分别理解为“开发预览代码已提供”“番茄单个样本已核验”“起点真实浏览器页面与资料采集已验证，普通HTTP仍受验证影响”“Obsidian 待验收”“未发布 Release 或插件市场版本”。

## 六、来源适配器架构（未发布）

`src/adapters/types.ts` 定义 `SourceAdapter`；`qidian.ts` 和 `fanqie.ts` 各自实现平台行为。`src/sources.ts` 的 `sourceAdapters` 是唯一平台注册入口，`Provider` 类型从注册表推导。模块间对数据模型使用 type-only 引用，运行时不依赖核心导入器。

| 接口 | 职责 |
|---|---|
| `provider` / `name` | 稳定来源标识、展示名称 |
| `matchUrl` | 官网域名和详情路径识别、字符串 ID、规范 URL |
| `identities` | 收集当前页身份；可使用注册表提供的 URL 解析器发现跨平台冲突 |
| `parse` | 提取资料、出处和平台警告；不访问网络或 Vault |
| `recoveryHint` | HTTP 失败后的平台补充导入提示 |
| `browserCapture`（可选） | 浏览器采集所需 DOM 选择器；未声明的平台拒绝书签采集及剪贴板接收 |

公共入口负责 URL 协议校验、DOMParser 解析、身份一致性验证、必填字段校验、获取时间与获取方式。`shared.ts` 提供文本、图片 URL、状态和页级身份工具。网络请求、封面保存、来源去重与 Vault 写入仍在 `Importer`；字段保护仍在 `merge.ts`，schema 保持 1，无数据迁移。

新增平台的步骤：核验真实作品详情页及封面 → 在 `src/adapters/` 实现接口 → 加入 `sourceAdapters` → 添加身份、解析及缺失字段测试 → 实测客户端。无须修改核心导入和合并逻辑。平台说明、UI 文案与真实支持范围应随新平台另行更新；当前未新增平台，书签仍仅声明起点采集能力。

书签真实点击、浏览器权限与协议唤起完整链路标为**待验收**。自动化中的隔离脚本执行不能代替这一项。Sandbox 客户端结果见验证记录顶部。
